# Speed Car — diagnostic, réparation et validation du 31 octobre 2026

**Statut : fonctionnel dans ChatGPT pour les sept outils actuellement exposés.** Deux conversations réelles ont été utilisées ; les reçus des actions physiques ont été relus directement dans le relais. Speed Car commande le Redmi : ce projet ne contient aucun jeu ni véhicule à piloter.

## 1. Causes démontrées

Trois couches distinctes expliquaient les constats :

- **Connexion OAuth inachevée.** Brave envoyait `Origin: null` au POST du formulaire sous `Referrer-Policy: no-referrer` ; le serveur répondait `403 Origine refusée`. Observation réseau réelle, cookie présent. Après correction, Chromium bloquait encore le retour OAuth à cause de `form-action 'self'` ; erreur CSP observée dans le journal du navigateur. Les tests HTTP directs n'exerçaient pas ces comportements du navigateur.
- **Droits du prototype conservés.** La configuration initiale ChatGPT demandait seulement `speedcar:test`, alors que les fonctions Android nécessitent aussi `speedcar:phone`. Une nouvelle demande a explicitement présenté les deux droits et `offline_access` avant consentement. Aucun ancien jeton de test n'a reçu silencieusement des droits physiques.
- **Mauvaise identité passée au gestionnaire de permissions.** `dev-6ae5a96e8a488191a89c47d2d513495b` est le nom du plugin. Son export officiel `.app.json` le relie à `asdk_app_6ae5a96e8a488191a89c47d2d513495b`. Le gestionnaire renvoyait `not_installed` avec les références dev/plugin ; avec l'identifiant d'application il renvoie **found**, nom Speed Car, réglage spécifique « Use my default ». La permission globale reste « Allow low-risk actions ». La recherche publique vide n'était pas une preuve d'absence de cette application privée.

Identifiants utiles :


Le suffixe `@openai-curated-remote` dans la référence du plugin ne désigne pas son serveur MCP. Le lien application/plugin est confirmé par l'export ; aucun changement de marketplace n'a été nécessaire.

## 2. Corrections et architecture réelles

Trajet : **ChatGPT → MCP HTTPS Cloudflare → Durable Object PhoneLink → WSS sortante authentifiée du Redmi → API Android → reçu natif persistant → ChatGPT**. Aucun PC, ADB, Tailscale ou port entrant dans le trajet des commandes. ADB a servi à installer et configurer l'application ; il reste indépendant du fonctionnement natif.

- Relais : `relay/src/index.ts`, `consent.ts`, `env.ts`, `mcp.ts`, nouveau `phone-link.ts`. OAuth/PKCE, découverte, droits explicites, identité et modèle épinglés, refus anonyme, délais bornés, reçus durables. `Referrer-Policy: same-origin` conserve le contrôle strict d'origine ; la CSP autorise uniquement l'origine de retour déjà validée par OAuth. Aucun joker ni désactivation du contrôle CSRF.
- Android : `MainActivity.kt`, `MediaVolume.kt`, `LinkService.kt`, `RemoteActions.kt`, `PairingStore.kt`, `CommandLedger.kt`, `BootReceiver.kt`, manifeste et dépendance OkHttp. Une connexion, un exécuteur d'effets, notification permanente avec Arrêter. Jeton appareil chiffré par Android Keystore ; aucune clé dans l'APK ou le dépôt.
- Reconnexion : temporisation croissante de 2 à 60 s avec aléa, détection de réseau ; aucune file d'attente d'effets hors ligne. Délais de commande 3 s pour état/volume, 5 s pour Brave. UUID obligatoire pour les écritures ; même UUID sur reprise. Historique borné à 200 commandes / 24 h ; après résultat incertain, relecture du reçu plutôt que nouvel effet.
- Diagnostic et preuves : scripts dans `relay/scripts/`, tests, README et ce rapport. Aucun nouveau service Windows ; builds exécutés dans l'environnement cloud. Autres plugins, processus et projets conservés.

## 6. Limites et revalidation

- YouTube : le reçu prouve l'intention ciblée et la reprise de Brave, **pas le chargement de l'URL**. Aucune commande de lecture vidéo n'a été envoyée ; l'état de lecture effectif de la page n'est pas inspecté par ce reçu.
- Audio : l'index STREAM_MUSIC ne prouve ni niveau acoustique de l'autoradio, ni absence d'interaction avec ChatGPT Voice. Bluetooth automobile non testé.
- Voix : non testée, volontairement retirée des prérequis par l'utilisateur. Pas de promesse fondée uniquement sur la réussite en texte.
- PC physiquement éteint : non testé pour préserver les autres tâches. L'architecture et les essais MCP cloud démontrent un trajet de commande sans le PC ; ne pas prétendre à un essai avec arrêt réel de Windows.
- Longue veille, redémarrage Android et autodémarrage HyperOS : préparés mais non validés. Récepteur de démarrage présent ; après la mise à jour observée, l'ouverture de Speed Car a été nécessaire à la reprise. Les permissions SDK ont été lues ; les réglages particuliers d'autodémarrage/fenêtres HyperOS n'ont pas été lus.
- Mise à jour APK : la superposition était repassée à false après 0.3.1, puis a été réaccordée et relue vraie. Revalider superposition, accès d'utilisation, exemption batterie et notifications après chaque mise à jour.
- OAuth : accès 1 h, renouvellement limité à 30 jours ; une réauthentification reste possible. Le paramétrage ancien ChatGPT conservait le droit de test seul. Si cela se reproduit, demander explicitement les deux droits avant le consentement. Les helpers PC `scope-phone.js` et `autoriser-owner.mjs` préparent cette autorisation sans afficher le secret ; ne pas les lancer hors d'un flux volontaire de connexion à cette application. Le secret propriétaire est conservé sous DPAPI pour l'administration ; cette phase de préparation ne constitue pas une liaison permanente au PC.
- Latence : traitements Android des deux commandes de volume ChatGPT mesurés à 58 et 189 ms ; Brave à 202 ms. Le délai ChatGPT inclut son raisonnement et ses échanges : le test Brave a montré environ 14 s de réflexion avec le mode élevé. Ne pas présenter les seules durées Android comme le délai ressenti.
- Tout changement de compte, identifiant, droits, versions, origine réseau ou autorisations impose une nouvelle lecture depuis un nouveau chat et une preuve d'effet réversible. Après un reçu incertain, relire ; ne pas réexécuter sous un nouvel UUID.

## 7. Trois évolutions proposées

1. Appairage et réautorisation personnels guidés, puis qualification de la reprise HyperOS après veille et redémarrage, sans dépendre d'une intervention ADB pour l'usage courant.
2. Catalogue de nouvelles actions et fournisseurs MCP avec droits limités par capacité, délais et preuve d'effet : navigation, médias et informations de trajet. Ne pas exposer de shell ni d'URL arbitraire par défaut.
3. Mesurer et réduire le délai ChatGPT complet avec un mode de commande adapté ; conserver les actions Android spécialisées et les réponses courtes. Le mode vocal sera un test séparé, lorsqu'il sera demandé.
