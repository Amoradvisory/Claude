# Speed Car 2.0.1 — livraison et vérifications

**Statut : partiellement fonctionnel.** L’application 2.0.1 est installée, le relais 2.0.1 est déployé, les 34 outils sont exposés. Une nouvelle conversation ChatGPT a effectivement appelé deux nouveaux outils Android. GPS / Maps / navigation et les accès sensibles restent à valider sur téléphone : les permissions nécessaires étaient désactivées lors de la lecture, puis l’appareil est devenu hors ligne à 13:00 UTC.

Ce projet est un assistant Android personnel, pas un jeu de voiture. Aucune fonction de partie, score ou pilote de véhicule n’est inventée.

## 1. Causes établies et incertitudes

- **Catalogue d’applications lent** : `NativeIntents.apps()` interrogeait tous les lanceurs et chargeait chaque libellé dans l’unique file des commandes. Un reçu Android a mesuré **10 373 ms**, au-delà de l’expiration de 5 s ; les commandes suivantes recevaient `busy`. Le sélecteur local d’applications utilisait aussi ce travail sur le thread principal. Correction : cache mémoire préparé par un worker transitoire, réponse immédiate `catalog_loading` à froid, aucun lancement différé, accès direct aux paquets / alias courants. Après préparation, le même filtre Maps est revenu en **56 ms** sur le Redmi. Le chemin froid non bloquant est couvert par trois tests JVM ; sa durée complète sur appareil n’est pas annoncée mesurée.
- **Nouveaux droits OAuth** : les anciens jetons ne contiennent pas les nouveaux droits privés. Une simple réponse d’outil `permission_required` ne déclenche pas le parcours standard de consentement MCP. Correction 2.0.1 : challenge HTTP 403 `insufficient_scope`, conservation des droits utiles existants, demande du seul droit privé nécessaire, métadonnées accessibles sous `/.well-known/oauth-protected-resource/mcp`. Aucun ancien jeton ni droit global n’est élargi. La réaction automatique de ChatGPT à ce nouveau challenge privé reste à tester.
- **Permissions Android** : lecture réelle sur 2.0.1 : localisation locale désactivée, localisation Android non accordée, superposition désactivée, notifications privées et écran désactivés. L’accès aux données d’utilisation, l’exemption d’optimisation batterie et les notifications ordinaires étaient autorisés. Les sessions médias refusaient l’accès faute de NotificationListener autorisé. Aucun de ces droits sensibles n’a été forcé.
- **Coupure externe actuelle** : à partir de 13:00 UTC, MCP renvoie `phone_offline`, ADB indique `device offline`, le port Tailscale du téléphone expire. Tailscale le déclare hors ligne, dernière présence `2026-11-01T13:00:00.1Z`. Cela démontre une indisponibilité simultanée des canaux ; cela ne permet pas de conclure à batterie vide, redémarrage, arrêt d’application ou restriction HyperOS. Pas de faux diagnostic de panne du relais.
- **Intégration ChatGPT** : l’actualisation des outils dans la configuration de l’application existante a permis les appels aux nouveaux outils dans un nouveau chat. L’identifiant canonique reste `asdk_app_6ae5a96e8a488191a89c47d2d513495b`. La référence `dev-…` et la recherche publique ne constituent pas un diagnostic d’absence. Les preuves de l’ancienne réparation 0.3.1 restent dans le dossier parent.

## 2. Corrections et fonctionnalités développées

Architecture conservée : Worker OAuth/MCP, Durable Object `PhoneLink`, WSS sortante, Kotlin natif, même paquet et appairage. Aucun nouveau service de surveillance périodique ; compilation dans le cloud pour préserver le PC à deux cœurs.

Fichiers principaux :

- `relay/src/capabilities.ts` : 27 nouveaux schémas / descriptions / délais / droits, anciens outils conservés.
- `relay/src/mcp.ts`, `index.ts`, `consent.ts` : dispatch, reçus, droits privés et consentement incrémental standard ; entrées JSON bornées.
- `relay/src/phone-link.ts` : négociation des capacités Android et compatibilité avec les anciennes connexions ; arguments persistés en empreinte, données privées expurgées, résultats privés transitoires.
- Android `NativeIntents`, `AppCatalog`, `LazyCatalog` : intents officiels, sélection sans ambiguïté, cache non bloquant.
- Android `LocationActions`, `LocationActivity`, `OperationLease` : localisation ponctuelle, âge / fournisseur / précision, annulation à expiration et révocation.
- Android `MediaActions`, `DeviceActions`, `AudioCallGuard`, `PlaybackGate` : sessions médias, volume absolu avec plafond, batterie / réseau, torche et signal de recherche borné ; arrêt du son si un appel commence.
- Android `PhoneNotificationService`, `PersonalActions`, `ScreenAccessService`, `SensitivePolicy` : notifications filtrées et secrets masqués, préparation d’intents personnels, TTS, contexte sémantique volontaire et gestes limités.
- Android `AssistantSettingsActivity`, `MainActivity`, `AndroidManifest.xml`, `CommandLedger`, `NativeCatalog`, `LinkService` : permissions révocables, destinations locales, câblage des capacités, métadonnées de reçus, conservation de l’idempotence et de la supervision existantes. Version native produite par BuildConfig.

La revue indépendante a identifié cinq points importants et deux mineurs. Les deux mineurs ont été requalifiés importants selon l’effet utilisateur, puis corrigés : mauvaise cause `clock_skew` avec un ancien APK et refus d’URI non web présenté comme indéterminé. Les autres corrections concernent la classification d’une notification entière, l’annulation GPS, l’interruption audio lors d’un appel, la visibilité du service TTS et l’interdiction d’exécuter une notification dont le PendingIntent n’ouvre pas une activité. Aucun mineur différé.

## 6. Limites et gestes indispensables

Lire [UTILISATION.md](UTILISATION.md) pour les chemins exacts de réglages, exemples, diagnostic et retour arrière.

Pour reprendre : vérifier Internet, ouvrir Speed Car, **Activer Speed Car** si nécessaire, obtenir **Connecté au relais**. Ensuite autoriser volontairement GPS ponctuel + localisation Android + ouverture d’applications par superposition. Les accès médias et caméra/torche sont indépendants. Maison se configure localement, sans me transmettre son adresse.

Ne pas confondre permissions Android et consentement OAuth. Si ChatGPT demande une reconnexion pour la localisation, accomplir ce consentement ; sa reprise automatique sur le nouveau challenge n’a pas encore été démontrée. Aucun écran protégé contourné. Aucun micro, contacts, SMS automatique, appel direct ou GPS permanent ajouté. Captures MediaProjection et clics / saisies arbitraires restent hors de cette version.

## 7. Trois évolutions à privilégier après ces essais

1. Parcours local de vérification guidée des permissions et d’un premier GPS / Maps, avec résultat clair sans données privées dans les journaux.
2. Activation volontaire liée au Bluetooth de la voiture et preuve de reprise après veille / changement de réseau / redémarrage, sans promettre de contourner HyperOS.
3. Capture MediaProjection à consentement Android par session et sélection contrôlée de contenu à partager, avant toute extension des interactions d’écran.

## 8. Décisions et reprise de développement

Décisions prises pendant l’exécution :

1. Implémenter directement selon la mission détaillée, sans étape supplémentaire d’approbation ; revue indépendante effectuée. Coût si le périmètre était mal interprété : version installée à revoir, retour arrière conservé.
2. Permissions sensibles accordées seulement volontairement dans Android, jamais par ADB ; coût : essais physiques suspendus tant qu’elles manquent.
3. Phase écran limitée au contexte sémantique et à Défilement / Retour ; MediaProjection, clics et saisies différés ; coût : pas de contrôle arbitraire des applications.
4. Requalifier deux défauts de diagnostic comme importants et les corriger ; coût : migration / validation supplémentaire, protégée par tests de régression.
5. Ne pas considérer la revue / compilation comme preuve matérielle ; coût : statut partiel tant que les essais Android / HyperOS / consentement privé réel manquent.

Pas de mineur différé. Les sauvegardes et commandes de retour arrière sont dans le guide. Branche de développement conservée, aucune fusion forcée ni effacement de données. Suite exacte : rétablir la liaison, vérifier les permissions réellement accordées, tester GPS puis Maps puis navigation, ensuite sessions médias et torche ; enfin une nouvelle conversation ChatGPT avec un outil privé, puis test mobile / veille / redémarrage contrôlé. Reprendre les UUID incertains par relecture, jamais par nouvel effet aveugle.
