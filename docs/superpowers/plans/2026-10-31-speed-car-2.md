# Speed Car 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native implementation, task by task, with a fresh final reviewer.

**Goal:** Transformer les commandes Android existantes en assistant personnel utile, Maps/GPS d'abord.
**Architecture:** Worker OAuth/MCP + PhoneLink DO existants, WSS sortante et Kotlin natif. Modules par capacité, permissions locales explicites ; résultats sensibles transitoires.
**Tech Stack:** Kotlin, Android framework API 31–35 sur Android 16, TypeScript/Zod/MCP Cloudflare, JUnit/Vitest.
**Spec:** docs/superpowers/specs/2026-10-31-speed-car-2-design.md et mission utilisateur « SPEED CAR 2.0 ».

## Global Constraints
- Conserver les sept outils existants et l'architecture ChatGPT → MCP → Cloudflare → Speed Car Android.
- UUID distinct par demande volontaire, même UUID sur reprise, consultation par phone_command_status.
- Aucun partage automatique ni permanent ; localisation ponctuelle, sans suivi permanent.
- Ne pas annoncer qu'un itinéraire est calculé si seule l'intention Android a été envoyée.
- Ne pas contourner les protections Android ni activer les permissions sensibles par ADB.
- Ne pas bloquer le thread principal Android ; ne pas exposer les données personnelles dans les journaux.
- API Android officielles, peu de dépendances, PC faible préservé ; construire dans le cloud.

## Review Focus
- Téléphone connecté mais APK ancien : unsupported_capability explicite, sans effet erroné.
- Expiration pendant un dialogue ou une acquisition : annulation et pas d'effet différé silencieux.
- Même UUID avec arguments différents : refus ; résultat sensible absent du stockage durable.
- Destination maison absente, nom d'application ambigu, URI non web : refus explicite.
- Plusieurs sessions média ou appel en cours : pas de commande sur la mauvaise session ni son de recherche pendant l'appel.
